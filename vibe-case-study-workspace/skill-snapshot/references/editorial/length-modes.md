# Article Length Modes

Length is an editorial choice based on story complexity and evidence depth. It is not an archetype and should not be selected from an average across other cases.

Count all reader-facing text: title, headings, captions, proof-block copy, and body. Exclude navigation, footer, image metadata, and production notes.

## Compact — 450–650 words

Use for one clear arc, one pivotal decision, and a small evidence set. This is closest to the density of Meng Xie's shorter project stories.

Suggested structure:

1. Hero claim and two or three proof blocks.
2. Context or concrete before state.
3. Project progression in two or three stages.
4. One distinctive product or AI-building decision.
5. Outcome, adoption signal, influence, and one earned lesson.

Compression rules:

- Keep only one detailed decision in prose.
- Move secondary interface decisions into captions or annotations.
- Merge output, outcome, adoption, and influence into the story rather than requiring four headings.
- Use three to five public visuals.

## Standard — 800–1,100 words

Use when the project contains a meaningful evolution, two or three consequential decisions, and enough receipts to show iteration or validation.

Suggested structure:

1. Hero claim, proof strip, and concise orientation.
2. Specific problem and prior workflow.
3. Two to four causal project stages.
4. Two or three decisions with constraints and evidence.
5. AI-building craft when a concrete episode supports it.
6. Outcome, adoption, influence, boundaries, and reflection.

Compression rules:

- Give each section one narrative job.
- Use technical detail only to explain a decision or constraint.
- Use four to seven public visuals.

## Extended — 1,300–1,800 words

Use for a multi-phase product, several stakeholder or platform constraints, meaningful alternatives, and a rich evidence set. Length alone does not make a case more senior.

Suggested structure:

1. Hero claim, proof strip, and orientation.
2. Context, stakes, and evidence-backed starting point.
3. Explicit project phases or version progression.
4. Three to five consequential decisions or experiments.
5. Build method and AI-collaboration evolution where evidenced.
6. Validation, adoption, influence, limitations, and transferable framework.

Compression rules:

- Preserve causality across phases; do not add generic UX-process sections.
- Use deeper evidence, not more adjectives or feature description.
- Use six to ten public visuals, each tied to a local claim.

## Selection protocol

Before drafting, show all three modes and recommend one:

```text
Compact — 450–650: best if you want [trade-off].
Standard — 800–1,100: recommended because [evidence-based reason].
Extended — 1,300–1,800: worthwhile only if [missing or available evidence].
```

Let the user choose. If they delegate the choice, use the shortest mode that can carry the strongest story without omitting a consequential decision.

If a draft falls below the range because evidence is thin, shorten the format or use Practice Note. If it exceeds the range, remove repeated explanation and secondary details before cutting causal evidence.
